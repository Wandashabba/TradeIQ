Design

An instrument panel for retail execution, not a marketing site. The previous mockups leaned on gradients, pill buttons and glow — the visual vocabulary of a landing page — for screens whose real job is to get a manager from “something is wrong” to “someone is fixing it” in one screen. These are rebuilt around density, hairlines and figures.

What changed

Removed

  • Gradient pill buttons and 40px sheet radii — a CTA is not the shape of a control you press forty times a day.
  • The blue glow behind every frame, dot and shadow.
  • Montserrat extrabold display headings — one sans now, including on the hero figure.
  • Tailwind CDN + Font Awesome — the generic-utility look is half of what read as machine-made.
  • Fake Google / Apple sign-in — the backend has no OAuth; the buttons were a lie.
  • The overlay drawer on desktop — a tap to see where you are.

Introduced

  • A desktop console for the manager — persistent rail, filter row, multi-column grid. Managers are on Flutter web.
  • Real charts — axes, hairline grid, target rules, hover crosshairs, and a table view behind every one.
  • 3px geometry. Nothing is a pill; panels are 4px.
  • A validated palette — run through the CVD/contrast checker, not eyeballed.
  • State is never color alone — severity is a bar + a dot + a word; deltas carry a sign.
  • Copy that matches the backend — rate limits, auto-created tasks, admin provisioning.

Manager console — desktop

Flutter web. The stats-dense surfaces: where a manager triages a morning.

Auth — mobile

The bezel stays rounded, because a phone is. Nothing inside it is.

Open question on sign-up. The backend has no public registration — an admin provisions users via POST /users. So screen 06 is reframed as workspace setup: it creates the Client (name + industry, which seed the scorecard weights) and its first admin. If self-serve signup was never intended, this screen should instead become “accept invite & set password”, and the landing CTA should read Request a demo.

The three series hues were validated against the #14161c surface: they clear the lightness band, the chroma floor, 3:1 contrast, and a worst adjacent CVD ΔE of 41.3 — well above the ≥12 target. Status hues clear 3:1 on the same surface and are always paired with an icon or a word, so a red row still reads as critical in grayscale. Tokens live in tokens.css; they mirror app/lib/core/theme/app_colors.dart.

Figures throughout are demo data. Visibility metrics (planogram %, facings, cleanliness) are produced by the Phase-1 CV stub — see docs/architecture/stubs-and-interfaces.md.
