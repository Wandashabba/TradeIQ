Field agent

The manager and the agent are the same product, the same palette and the same tokens — but they are not the same design problem. A manager sits at a desk triaging many things at once, so density is a feature. An agent is standing in an aisle with one hand on a shelf, in bad light, often with no signal, doing one thing at a time — and asking one question all day: is my work safe?

Two different problems

Manager console

  • Density is the point. Twelve panels, hairline rules, 12.5px type.
  • Actions top-right — the mouse is already there.
  • Reading, comparing, deciding. Rarely typing.
  • Always online, on a big screen.
  • Answers: what is broken, and who is fixing it?

Field agent

  • One thing at a time. Full-screen sections, 15px type, ≥48px targets.
  • Actions at the bottom — that is where the thumb is.
  • Counting, not typing. A ± stepper beats a keyboard that covers half the screen and needs the other hand.
  • Offline is normal, not an error state.
  • Answers: where am I, what’s left, and is my work safe?

The visit

Design decisions

Sync is never hidden

The app is offline-first and today tells the agent nothing — no pending count, no last-synced time, no failure. Every agent screen now carries the answer, and one screen lists the whole queue. “Saved on this phone” is a promise, so it has to be visible.

The store sets the order, not us

A checklist hub, not a wizard. You cannot count stock while the aisle is blocked by a delivery. The agent works in whatever order the store allows; the app tracks what is done and what still blocks submit.

The thumb is the cursor

Primary actions sit in a bottom bar, never top-right. Counts use a 54px ± stepper instead of a text field: the keyboard covers half the screen and needs the hand that is holding the shelf.

A blocked button explains itself

Submit is disabled until the required sections are done — and it says which. A disabled control with no reason is a dead end, and a dead end in a store is a phone call to the manager.

Zero is a finding, not a blank

Zero units on shelf is the most valuable thing an agent can record — it raises the task. It is styled as a finding, and the row says what it will do, rather than looking like an empty field.

Unmeasurable ≠ failure

A dimension with nothing to measure shows “—”, never 0. No staff on shift is not the agent scoring nothing for capability. This mirrors the server, which now excludes it from the weighted total (#93).

What this fixes in the current app

A stepper with no titles

audit_shell_screen.dart renders Step(title: SizedBox.shrink()) — nine sections, no names, no progress. The agent cannot see where they are or what is left.

No sync feedback at all

There is no pending count, no last-sync time and no failure surface anywhere in the app, despite every capture going through an outbox.

No route screen

Agents get the manager's beat-plan list behind a role gate. There is no “my day” at all (#52), and beat plans have no recurrence (#98).

Visit hub

PR 4
Today + submit outcome

The route screen (#52) and the submit gate/score outcome. Needs GET /beatplans?date= for an agent’s own stops — that endpoint does not exist yet.

What the API cannot back yet. The route screen needs today’s stops for the signed-in agent (GET /beatplans?date=&agent=me) — not available today. Distance-to-store is computed on-device from the outlet’s lat/lng, which does exist. The “3 open tasks from last visit” row needs GET /tasks?outletId=, which does exist. The order screen’s promo pricing does not (#99) — the mock says so on the screen rather than implying it works.
