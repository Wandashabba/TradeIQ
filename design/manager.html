Manager console

A manager opens this at 08:00 with one question: what is broken, and who is fixing it? Everything above the fold answers that. The 375px phone frame couldn’t — it forced a scroll between the score and the alerts causing it, so the two facts you have to hold together were never on screen together.

Design decisions

Score, then cause, then who

Execution score leads with its trend and its target. Immediately right of it sits what is dragging it down — and every row is a link into the thing you’d do about it. Summary, cause, action: one screen.

Charts, not decoration

Axes, a target rule, a hover crosshair, and a table view behind every chart. A single hue per chart; length carries magnitude, so color is free to carry status instead.

State survives grayscale

Severity is a bar, a dot and a word. Deltas carry ▲/▼ plus a sign. Print it, or read it with deuteranopia, and nothing is lost.

One filter row, not per-panel filters

Territory, channel and date range sit above everything they scope, so every panel is guaranteed to be showing the same slice. A filter inside a card is a lie waiting to happen.

Color is spent, not sprayed

Blue is brand and interaction. Red is consequence. Tasks 12 is muted; Alerts 3 is red because those three breach. Everything else is ink.

Honest to the backend

Rules named as they exist (oos_any_sku), auto-created task IDs shown, the CV-stub caveat printed on the page. The mockup doesn’t promise what the API can’t serve.

Implementation map

Theme + core widgets

Port tokens.css into AppColors/AppTheme (squared radii, one type family). Add StatTile · LedgerRow · StatusChip · FilterBar · PanelCard to core/widgets/. Purely additive — no screen changes yet, so zero regression risk.

PR 2
Console shell

Replace the drawer in manager_scaffold.dart with a responsive rail (expanded ≥1080px, collapsed below, drawer on phone). Every one of the 18 manager screens inherits it.

PR 3
Dashboard

Hero score + trend from GET /trends/scorecards; needs-attention from GET /alerts + GET /tasks; KPI strip from GET /dashboard; territory bars from GET /territories/:id/coverage. Charts need a Flutter chart package — none is in pubspec.yaml today.

PR 4
List screens

Alerts first, since it establishes the severity pattern; then mechanically across Tasks, Orders, Users, Webhooks, Incentives, Territories.

Static HTML · tokens in tokens.css · no build step, no CDN framework. Demo figures throughout.
